🧱Builder Flow
1
Landing or GitHub
builders-diary.com 또는 GitHub README에서 유입
— 여기서 가치 확인 후 설치 결정
2
터미널에서 한 줄
pip install builders-diary
또는 uvx builders-diary
→ PATH에 커맨드 등록
install
3
MCP 등록 (1회, 불가피)
Claude Desktop / Hermes / Cursor config에
"builders-diary": {"command": "builders-diary"} 추가
→ 에이전트 재시작
config 편집 · ~60초
이게 유일한 마찰 지점. Landing에서 config snippet 복사 버튼 필수.
4
첫 호출 — 자동 셋업
에이전트에서 @builders-diary 처음 실행

MCP가 자동으로:
· ~/builders-diary/ 폴더 생성 (Obsidian 방식)
· ~/.builders-diary/config.json 생성
· Supabase에 user_id 등록
· 프로필 URL 발급: builders-diary.com/u/[id]
auto · 사용자 입력 없음
5
매일: 작업 → 호출 → 확인
세션 끝에 @builders-diary

Step 1 — 자동: 컨텍스트 분석 → 프로젝트·목표·제목·태그 제안
Step 2 — 30초: "맞아" 또는 수정
Step 3 — 자동: 로컬 파일 생성 + Supabase 동기화
반복 루프
6
이력서에 링크 삽입
MCP가 Step 3에서 반환:
builders-diary.com/r/[record-id]

이걸 이력서 불렛 옆 링크로 붙임
→ 리크루터가 클릭하면 기록으로 바로 이동
share

이력서 불렛 옆 링크 클릭
builders-diary.com/r/[record-id]

builders-diary.com 랜딩에서
도구 / 마인드셋 태그로 빌더 검색
예: claude-code end-to-end supabase
discovery
C
빌더 프로필 탐색
builders-diary.com/u/[id]

· 프로젝트 → 목표 → 기록 3층
· 판단이 보이는 카드 (형용사 없음)
· 태그 필터로 관련 기록만 추출
read-only
